# НОТАЛЕКС — Google и Яндекс, инструкция публикации

## Состояние проекта

Это **работающая статическая версия сайта** с прежним оформлением. Подготовлены Google Tag Manager (GTM), события для Google Analytics 4 / Google Ads, Яндекс Метрика, SEO, превью ссылок, robots, favicon и генератор Sitemap.

Пока **нет реального домена и номеров счётчиков**, **никакая аналитика НЕ загружается**. Это сделано намеренно. Нет ни выдуманных меток, ни фиктивной статистики. Google Analytics, Google Ads и Яндекс Метрика не «подключены к аккаунтам»: потребуется действие владельца.

Продуктивная версия **не добавляет никаких видимых изменений дизайна**, если отслеживание не включено. После активации измерений появляется отдельное минимальное согласие на аналитику (возможна замена на юридически проверенную CMP). Нельзя включать сбор данных без проверки применимых правил и корректного информирования посетителей.

## Состав

- `index.html`, `style.css`, `hero-reference.css`, `navigation.css`, `script.js` — прежний сайт.
- `tracking-config.js` — отключённая конфигурация идентификаторов.
- `tracking.js` — согласие + загрузка GTM / Метрики + единые события контактов. **Нет GTM без согласия**.
- `tools/publish.py` — создаёт папку для публикации с настоящим HTTPS доменом, canonical, Open Graph, Search Console / Вебмастер, sitemap.xml, robots.txt и JSON-LD.
- `favicon.ico`, `favicon.png`, `og-preview.jpg` — брендовая иконка и превью без вмешательства в дизайн.

## 1. Домен и хостинг

1. Купите домен, разверните сайт на **HTTPS** со стабильным адресом (одно главное www/без www), настроив 301 редирект дублей через хостинг.
2. Убедитесь, что адрес, наименование, телефон и профессиональный статус адвоката отражены корректно. Правовой статус «адвокатское бюро» требует отдельного подтверждения владельцем.
3. Сформируйте папку публикации:

```bash
python tools/publish.py --domain https://ВАШ-ДОМЕН.ru --out public
```

`ВАШ-ДОМЕН.ru` заменить настоящим приобретённым доменом. Загрузите содержимое `public/` в корень сайта. В `robots.txt`, `sitemap.xml` и canonical автоматически появится домен, а в HTML — JSON-LD `LegalService` на основе указанных на сайте фактов. Перед публикацией проверьте их достоверность.

## 2. Google Search Console

- Создайте ресурс типа «Домен» и подтвердите через DNS (предпочтительно) либо «URL-prefix» через проверочный HTML-тег.
- При втором варианте можно передать **только точное значение токена** из Google в `--google-verification ...`.
- После публикации отправьте `https://ВАШ-ДОМЕН.ru/sitemap.xml`, изучите индексацию и статус страниц.
- Главная пока одна: разделы с `#` — не отдельные URL, их нельзя вносить в Sitemap.

## 3. Яндекс Вебмастер

- Добавьте HTTPS-адрес, подтвердите владение, отправьте sitemap.xml и проверьте обход/индексацию.
- Для способа с метатегом добавьте `--yandex-verification ЗНАЧЕНИЕ` в команду сборки.

## 4. Google Tag Manager → GA4 → Google Ads

1. Создайте **Google Tag Manager web container** — получите ID `GTM-...`.
2. Создайте **Google Analytics 4**, получите `G-...` (Measurement ID). В интерфейсе GTM создайте **Google tag** с этим `G-...`, с корректными Consent Settings. Не вставляйте второй самостоятельный GA4 script в HTML — иначе получите двойной сбор данных.
3. Настройте в GTM Custom Event trigger `notalex_contact`. Доступные переменные Data Layer:
   - `contact_method`: `phone`, `whatsapp`, `telegram`, `consultation_anchor`, `map_link` (последнее только при наличии исходящей ссылки на карту).
   - `contact_goal`: `click_phone`, `click_whatsapp`, `click_telegram`, `contact_primary`, `open_map`.
4. На этом триггере создайте **GA4 Event tag** с именем `contact_click` и параметром `contact_method`. Не передавайте телефон, имя или другие персональные данные клиента в GA4 / Ads. Установите необходимые consent checks.
5. В Google Ads можно создать конверсию на базе GA4 события либо отдельный Ads conversion tag через GTM. Начните с нажатий по средствам связи как **микроконверсий**. Не приравнивайте клик по телефону к состоявшемуся звонку или заявке. Для реальных лидов используйте проверенные данные CRM/коллтрекинга, где применимо.
6. Проверяйте через GTM Preview, GA4 DebugView и реальные переходы. Для рекламы полезна Auto-tagging (GCLID) — сайт не удаляет параметры URL.

## 5. Яндекс Метрика и Директ

1. Создайте счётчик Метрики и получите реальный цифровой ID.
2. В Метрике создайте «Целевое событие» с идентификаторами **точно**: `click_phone`, `click_whatsapp`, `click_telegram`, `contact_primary`. `open_map` будет срабатывать лишь если добавите отдельную ссылку открытия карты (клик внутри iframe не перехватывается). 
3. При использовании автоматических целей не считайте те же действия дважды. Проверьте цели на рабочем сайте.
4. Подключите Метрику к Директу, используйте метки рекламы `yclid` и UTM при необходимости. Скрипт их не изменяет. Для оценки качества нужны реальные обращения.

## 6. Когда готовы юридические сведения / согласие / аккаунты

Выполните **одну** команду для формирования новой публичной папки с отключённой по умолчанию аналитикой до выбора посетителя:

```bash
python tools/publish.py --domain https://ВАШ-ДОМЕН.ru --gtm GTM-ВАШID --metrika 12345678 --enable-consent-ui --privacy-policy-url https://ВАШ-ДОМЕН.ru/privacy/ --out public
```

`GTM-ВАШID` и `12345678` — **образцы формата**, не настоящие идентификаторы. `https://ВАШ-ДОМЕН.ru/privacy/` должен вести на реально опубликованную юридически проверенную политику. Нужна работающая страница политики, которая в этот пакет **не входит** (невозможно заполнить её реальными сведениями оператора без данных владельца). Перед выполнением замените реальными. Можно задать только GTM или только Метрику. Пока пользователь не нажмёт «Только аналитика» или «Аналитика и реклама», внешние теги не загрузятся.

**Согласие:** перед живым запуском оцените российские и другие применимые требования о персональных данных, трансграничной передаче данных, cookies и рекламе. Подготовьте действительную политику обработки данных и текст согласия; при необходимости замените минимальный технический баннер проверенным CMP. После активации внизу страницы появляется ссылка «Настройки аналитики» для повторного выбора. При отзыве согласия могут потребоваться дополнительные действия CMP и поставщиков тегов. Страница содержит встроенный сторонний iframe Яндекс.Карт, который надо отдельно оценить в рамках приватности.

## 7. Техническая проверка после загрузки на домен

- HTTPS, DNS, `robots.txt`, `sitemap.xml`, canonical, favicon, og:image доступны без авторизации.
- Все кнопки и мобильное меню работают; на 390, 768, 1024 и 1440 px нет горизонтального переполнения.
- GTM / Метрика **не** появляются в Network до согласия; после выбора согласия запросы уходят лишь к разрешённым инструментам.
- Срабатывают события `notalex_contact` в GTM Preview и `reachGoal` в Метрике (без дублей).
- Яндекс Карта загружается при интернет-соединении (в локальном офлайн-превью она может быть недоступна).
- Проверить реальную скорость и Core Web Vitals уже на домене через PageSpeed Insights / Lighthouse: офлайн-проверка не может заменить сетевые условия реальных посетителей.
- Реклама адвокатских услуг и юридический статус/реквизиты требуют проверки владельцем до запуска кампаний.

## Почему размер архива значительно уменьшился

Из рабочей сборки удалены неиспользуемые копии фотографий, старые PNG из предыдущих попыток, неиспользуемые SVG и дополнительные версии архитектурных гравюр. Все **фактически используемые** HTML/CSS изображения оставлены без переименования и без изменения графики. Исходная папка предыдущей версии не изменена.
